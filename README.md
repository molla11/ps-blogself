# PS-Blogself

PS-Blogself는 C·C++·Python 코드의 수정 과정을 풀이 글로 정리하는 VS Code 확장입니다. AI가 제안한 메모에 풀이를 바꾼 이유를 보태고, 그 메모로 블로그 초안을 만들 수 있습니다.

[첫 글 만들기](#첫-글-만들기) · [글 내보내기](#글-내보내기) · [크레딧과 개인정보](#크레딧과-개인정보)

VS Code의 확장 탭에서 `Shinem-dev.ps-blogself`를 검색해 설치하세요. 처음 설치하면 Welcome 탭이 열립니다. 다시 열려면 명령 팔레트에서 **PS-Blogself: 시작하기 (Welcome)**를 실행하세요. [Marketplace](https://marketplace.visualstudio.com/items?itemName=Shinem-dev.ps-blogself) · [VSIX 다운로드](https://github.com/molla11/ps-blogself/releases/latest)

### 첫 글 만들기

자동 메모는 기본으로 켜져 있습니다. 로그인 후 코드 변경이 쌓이면 글을 쓰기 전에도 해당 파일의 코드와 변경 기록을 AI에 보내 메모를 만듭니다. 원할 때만 메모를 만들려면 먼저 **설정 → 글쓰기 → 수정 기록으로 메모 자동 생성**을 끄세요.

1. 사이드바 하단의 **로그인**을 누르세요. 브라우저에서 Google 또는 GitHub로 로그인한 뒤 VS Code로 돌아옵니다.
2. **예제 코드로 테스트**를 누르세요. 중복된 숫자를 제거하는 파이썬 예제가 열립니다. 내 풀이로 시작하려면 **이 창의 코드 파일**에서 파일명 옆 **글쓰기**를 누르면 됩니다.
3. **풀이 메모**를 여세요. 메모가 비어 있으면 사이드바의 **메모 생성**을 누르세요. 예제라면 “중복을 없애면서 입력 순서도 유지하려고 `dict.fromkeys`를 썼다”처럼 풀이를 바꾼 이유를 한 줄 보태 보세요.
4. **본문 편집 → 이 메모로 초안 만들기**를 누르세요. 글이 완성되면 같은 화면에서 제목과 본문을 고칠 수 있습니다. 수정한 내용은 자동으로 저장됩니다.

### 풀이 메모와 본문 다듬기

- **코드 변화 보기**를 펼치면 메모가 가리키는 수정 내용을 볼 수 있습니다. **범위 조정**으로 글에 담을 구간을 고르고, 빠진 시행착오는 **메모 추가**로 끼워 넣으세요.
- **글 구성**과 **문체**는 초안을 만들기 전에 사이드바에서 고르세요. **수정 과정 중심**은 시도한 순서대로, **풀이 해설 중심**은 최종 코드를 중심으로 씁니다. 알고리즘의 원리부터 설명하고 싶으면 **알고리즘 설명 중심**을 고르세요.
- **본문 편집**에서 빈 문단에 `/`를 입력하거나 **＋**를 누르면 코드 블록, 표, 이미지를 넣을 수 있습니다. Markdown을 직접 편집하려면 **설정 → 고급 → 글쓰기에서 Markdown·미리보기 표시**를 켜세요.

### 글 내보내기

본문을 열고 사이드바에서 **내보내기**를 펼치세요.

| 메뉴 | 이렇게 쓰세요 |
| --- | --- |
| **Markdown 복사** | 제목과 본문을 복사해 다른 편집기에 붙여넣으세요. |
| **Markdown 파일 저장** | `풀이.md`로 저장하면 로컬 이미지는 옆의 `풀이.assets` 폴더에 담깁니다. 글과 함께 옮기세요. |
| **HTML 파일 저장** | 로컬 이미지까지 담은 HTML 파일 하나가 생깁니다. 브라우저로 열어 글의 서식을 확인할 수 있습니다. |

**Ghost 블로그에 올리려면** 블로그 주소와 Admin API 키를 **Ghost 연결 설정**에 입력하세요. **Ghost 초안 저장**으로 비공개 초안을 올리고, 공개할 때 **Ghost에 게시…**를 눌러 확인하세요. **설정 → 내보내기 → Ghost 자동 업로드**는 기본으로 꺼져 있습니다. 켜면 **Draft**는 비공개로 저장하고 **Publish**는 추가 확인 없이 공개합니다.

[브라우저 확장 설치 안내](https://ps-blogself.shinem.dev/browser-extension)에서 설치 가능 여부를 확인하세요. 이미 설치했다면 블로그의 빈 글쓰기 화면에서 **PS-Blogself 내보내기**를 여세요. VS Code와 같은 계정으로 로그인한 뒤 **내 글**에서 글을 고르고 **티스토리에 넣기**처럼 블로그 이름이 붙은 버튼을 누르세요. 로컬 이미지는 표시된 위치에 첨부하고, 발행은 블로그에서 마무리하세요.

공통 태그가 있다면 **설정 → 내보내기 → 추가할 태그**에 `PS, 알고리즘`처럼 입력하세요. Markdown·HTML·Ghost로 내보낼 때 반영됩니다.

## 수정 기록과 설정

사이드바 **코드 파일**에서 파일을 한 번 누르면 **수정 기록 보기**로 변경 내용을 읽거나 **글쓰기**로 메모를 편집할 수 있습니다. 기록이 없는 파일도 Welcome에서 **글쓰기 → 메모 생성**을 누르면 마지막 저장본으로 시작합니다. 편집 중에 파일 목록으로 돌아가려면 사이드바 왼쪽 위의 **처음 화면**을 누르세요. 도구가 다시 필요하면 편집기에서 **글쓰기 도구 열기**를 누르세요.

기록할 폴더와 확장자는 **설정 → 수정 기록**에서 고릅니다. 기본값인 **현재 열려있는 모든 파일**에는 작업 폴더 밖에서 연 파일도 포함됩니다. **현재 폴더로 설정 (이 창)**을 고르면 해당 창에만 적용되고, 창을 다시 열면 작업 공간에 저장된 경로로 돌아갑니다.

<details>
<summary>자동 기록과 메모 생성 시점</summary>

저장하면 로컬에 기록이 남습니다. 입력 중에도 10초간 멈추거나 30초 동안 계속 수정하면 기록하며, 연속된 작은 수정은 한 항목으로 묶일 수 있습니다. 파일당 기록 한도는 UTF-8 기준 512KiB입니다.

자동 메모는 의미 있는 변경을 모아 만듭니다. 편집을 5분간 멈추거나, VS Code 창을 30초 이상 떠나거나, 다른 기록 대상 파일로 전환한 지 1분이 지나면 확인합니다. 같은 파일을 백그라운드에서 다시 확인하는 간격은 보통 10분입니다. 파일 메뉴나 수정 기록을 열면 바로 확인합니다. 메모가 12개 찼다면 **메모 다시 생성**으로 구성을 새로 잡을 수 있습니다.

## 저장과 복원

- **이전 초안을 다시 쓰고 싶어요.** 사이드바의 **글 버전**에서 먼저 읽어 보고 **이 버전 사용**을 누르세요. 기기에 이전 버전을 최대 20개 보관합니다. 글 생성 도중 따로 고친 내용이 있으면 **새 결과 적용**과 **현재 내용 유지** 중에서 고를 수 있습니다.
- **창을 닫았다가 이어 쓰고 싶어요.** 같은 파일의 **글쓰기**를 다시 열면 진행하던 작업을 확인할 수 있습니다. 다른 창에서 편집 중이라 읽기 전용으로 열렸다면 **이 창에서 편집**을 누르세요.
- **브라우저에 방금 고친 글이 안 보여요.** VS Code와 브라우저 확장이 같은 계정인지, VS Code에 **서버 동기화됨**이 표시되는지 확인하세요. 연결이 끊겼다면 같은 계정으로 다시 연결할 때 편집본을 보냅니다. 이전 확장에서 만든 로컬 글은 명령 팔레트의 **PS-Blogself: 기존 로컬 글을 서버 작업에 연결**로 원래 작업을 고르세요.

## 개발하기

Node.js 24, pnpm 12.16.1, VS Code 1.108.1 이상을 기준으로 개발합니다.

```sh
git clone https://github.com/molla11/ps-blogself.git
cd ps-blogself
pnpm install --frozen-lockfile
code .
```

**F5 → Run Extension**으로 Extension Development Host를 엽니다. 터미널에서는 `pnpm dev /path/to/problem-folder`를 사용할 수 있습니다.

소스 변경은 자동 빌드하며, 확장 코드는 **Developer: Reload Window**로 다시 적용합니다. 개발 환경 변수는 `.env.example`을 참고해 확장 저장소 루트의 `.env`에 지정합니다. `.env`는 Git과 설치 패키지에서 제외됩니다.

Windows·WSL·macOS에서 같은 방식으로 실행합니다.

## 검증

클라이언트의 타입·저장 로직·화면 동작은 다음 명령으로 검사합니다. 이 검사들은 실제 AI 작업을 실행하지 않습니다.

```sh
pnpm compile
pnpm test:unit
pnpm exec playwright install chromium
pnpm test:ui
```

```sh
pnpm test:host
```

통합 테스트는 기록·자동 준비·스트리밍·초안 복원·사용량과 Ghost 내보내기를 확인합니다. Linux에서는 GUI 디스플레이가 필요하며 `VSCODE_EXECUTABLE`로 VS Code 실행 파일을 지정할 수 있습니다.

## VSIX 다운로드와 배포

[최신 GitHub Release](https://github.com/molla11/ps-blogself/releases/latest)의 **Assets**에서 `ps-blogself-<버전>.vsix`를 받아 VS Code의 **Extensions: Install from VSIX…**로 설치합니다.

일상 개발은 `develop`에 직접 커밋하고 `git push origin develop`으로 올립니다. GitHub Actions는 `develop`과 `main`의 푸시 및 두 브랜치 대상 PR에서 단위 테스트와 Chromium UI 테스트를 실행합니다. 타입 검사와 린트를 통과한 VSIX를 새 VS Code 프로필에 설치하고 Welcome 탭이 열리는지 확인합니다. 통과한 패키지는 해당 실행의 **Artifacts**에서 14일간 받을 수 있습니다. 별도의 로컬 테스트 백엔드가 필요한 전체 통합 테스트는 위의 `pnpm test:host`로 실행합니다.

새 버전을 배포할 때는 `develop`에서 `package.json`의 `version`을 올리고 `main`으로 병합합니다. `main`의 CI가 통과하면 같은 VSIX가 `v<버전>` GitHub Release에 자동으로 올라갑니다. 이미 배포한 버전의 VSIX는 보존합니다.

## 설치 패키지 만들기

```sh
pnpm package:vsix
code --install-extension dist/ps-blogself.vsix
```

VS Code의 **Extensions: Install from VSIX…**에서도 설치할 수 있습니다. 설치 후 서비스에 로그인해 사용합니다.
