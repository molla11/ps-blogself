# PS-Blogself

코드가 바뀐 과정을 풀이 블로그로 정리하는 VS Code 확장입니다. 수정 기록에서 파일을 고르면 AI가 글에 사용할 구간과 설명을 준비하고, 사용자는 내용을 확인한 뒤 글을 만들고 편집할 수 있습니다.

이 저장소에는 **공개 클라이언트인 VS Code 확장**만 포함합니다. 로그인, AI 작업 실행, 사용량 집계를 담당하는 백엔드는 별도로 운영하는 비공개 소프트웨어입니다. 서버 코드·모델 설정·내부 프롬프트·운영 자료는 공개 범위에 포함하지 않습니다.

**글 준비와 생성에는 실행 중인 백엔드와 서비스 로그인이 필요합니다.** 클라이언트에서 AI를 직접 호출하거나 서버 없이 글을 생성하는 모드는 제공하지 않습니다. 기본 서비스 주소는 `https://psb-backend.shinem.dev/api`입니다.

## 사용하기

1. VS Code에 확장을 설치하고 PS-Blogself 사이드바를 엽니다.
2. **로그인**에서 브라우저 인증을 완료합니다.
3. C·C++·Python 파일을 수정하고 저장합니다. 기록이 없다면 **샘플로 시작**으로 사용 흐름을 확인할 수 있습니다. 샘플의 AI 작업도 서버에서 실행합니다.
4. 수정 기록을 열어 AI가 준비한 구간과 설명을 확인합니다. 설명은 바로 수정할 수 있습니다.
5. **글쓰기 열기 → 이대로 글쓰기**로 초안을 생성합니다. 완성된 글은 VS Code 안에서 편집하고 내보냅니다.

파일을 저장하기만 할 때는 AI를 호출하지 않습니다. 로그인한 상태에서 수정 기록을 검토하면 글쓰기 밑작업을 준비하며, 같은 이력에 대한 준비 결과는 재사용합니다. 자동 준비는 설정에서 끌 수 있습니다. 사용자가 편집한 설명과 본문은 새 AI 결과로 자동 덮어쓰지 않습니다.

## 수정 기록과 설정

- 파일 행을 클릭하면 **파일 열기 / 수정 기록 보기**를 선택할 수 있고, 더블클릭하면 파일이 열립니다.
- 최근 변경 기록은 처음 20개를 표시하고 스크롤하면 이전 기록을 이어서 불러옵니다.
- 제목 옆 검색 버튼으로 전체 기록의 파일명을 검색합니다. 검색어에 `/` 또는 `\`가 있으면 경로도 검색합니다. 검색어를 지우면 최근 20개부터 다시 표시합니다.
- 사이드바 제목 오른쪽 **설정**에서 활성 경로, 대상 확장자, 기록 여부, 글쓰기 미리 준비를 변경합니다.

활성 경로의 기본값은 **현재 열려있는 모든 파일**입니다. 이 상태에서는 워크스페이스 밖에서 연 파일도 대상 확장자에 맞으면 기록합니다. 폴더를 지정하면 해당 경로 안의 파일만 기록하고, 재설정 버튼을 누르면 기본값으로 돌아갑니다.

활성 경로·대상 확장자·기록 여부는 워크스페이스별로 저장합니다. 같은 워크스페이스를 연 창끼리는 설정을 동기화하고, 검색어와 스크롤 위치는 각 창에서 유지합니다.

## 글쓰기와 내보내기

글 구성은 **수정 과정 중심**, **풀이 해설 중심**, **알고리즘 설명 중심** 중에서 선택합니다. 문체는 했다/이다체, 합니다체, 해요체, 간결한 메모체 또는 사용자 지정으로 설정할 수 있습니다. 선택만으로 AI 작업을 시작하지 않으며 다음 준비·작성 요청에 반영합니다.

Lexical 기반 블록 편집기에서 제목·목록·인용·코드·표·이미지를 편집합니다. **+** 또는 빈 문단의 **/**로 블록을 넣고 왼쪽 핸들로 이동합니다. 이미지 파일 선택·붙여넣기·드롭과 캡션 편집을 지원합니다. **목차**로 제목 사이를 이동하거나 **Markdown**으로 원문을 편집할 수 있습니다.

**내보내기**에서 다음 기능을 제공합니다.

- Markdown 복사 또는 파일 저장. 로컬 이미지는 문서 옆의 이미지 폴더에 함께 저장합니다.
- HTML 파일 저장. 로컬 이미지를 포함하므로 브라우저에서 바로 열 수 있습니다.
- Ghost 연결 및 초안 저장. 공개 게시는 별도 확인을 거치며 이후에는 같은 글을 갱신합니다. Ghost에서 수정한 글은 자동으로 덮어쓰지 않습니다.

Ghost 연결에는 해당 사이트의 Admin API 키가 필요하며 키는 VS Code SecretStorage에 저장합니다. 표·체크 목록은 Ghost HTML 카드로 변환합니다. 자세한 지원 범위는 [편집기와 Ghost 내보내기](docs/lexical-ghost.md)를 참고하세요.

## 저장과 복원

수정 기록과 편집 초안은 로컬에 저장합니다. 이전 글은 최대 20개 버전을 보관하며 내용이 같거나 줄 끝 공백만 다른 경우에는 버전을 추가하지 않습니다.

같은 VS Code 프로필·실행 환경의 창들은 기록과 초안을 공유합니다. 같은 글은 한 창에서 편집하고 다른 창에서는 읽기 전용으로 확인합니다. **이 창에서 편집**으로 편집권을 옮길 수 있습니다.

서버에 제출한 작업은 창을 닫아도 계속됩니다. 다시 열면 기존 작업 ID로 결과를 조회하며, 연결 실패만으로 새 생성 요청을 자동 제출하지 않습니다. 서비스에 연결할 수 없어도 설치된 확장의 기존 기록 열람과 로컬 초안 편집은 가능합니다.

코드 파일은 UTF-8 기준 512KiB까지 기록합니다. 큰 파일의 새 기록은 중지하되 기존 이력은 유지하며, 긴 이력은 AI 요청에 들어갈 범위를 줄여 처리합니다.

## 계정·크레딧·전송 데이터

사이드바의 무료 사용량·한도·유료 잔액은 서버가 제공하는 크레딧 정보를 표시합니다. 계정이나 사용량 버튼에서 세부 내용을 확인할 수 있습니다. 조회에 실패하면 사용량 확인 불가로 표시합니다.

글을 준비하거나 생성할 때 선택한 코드·변경 내용·설명·작성 요청이 백엔드와 서버에서 사용하는 AI 서비스에 전송됩니다. 로그인 토큰은 VS Code SecretStorage에 저장합니다. Ghost로 내보낼 때는 선택한 글과 필요한 이미지를 해당 Ghost 사이트로 전송합니다.

## 클라이언트 개발

Node.js 24, pnpm 11, VS Code 1.108.1 이상을 기준으로 개발합니다. **서비스 백엔드에 접근할 수 있어야 개발 실행과 통합 테스트가 가능합니다.** 이 저장소에는 백엔드 실행 파일이나 AI 서비스 키가 포함되지 않습니다.

```sh
git clone https://github.com/molla11/ps-blogself.git
cd ps-blogself
pnpm install --frozen-lockfile
```

운영 서비스에 연결할 때는 별도 `.env` 없이 기본 주소를 사용합니다. 로컬 또는 별도 개발 서버를 제공받았다면 `.env.example`을 `.env`로 복사하고 주소를 지정합니다. 로컬 서버는 먼저 실행되어 있어야 합니다.

```dotenv
PSB_API_URL=http://127.0.0.1:4000/api
```

```sh
pnpm check:backend
code .
```

**F5 → Run Extension**을 누르면 백엔드 연결 확인과 빌드 후 Extension Development Host가 열립니다. 터미널에서는 `pnpm dev /path/to/problem-folder`를 사용할 수 있습니다. 서버에 연결할 수 없거나 API 버전이 맞지 않으면 개발 실행을 중단합니다.

소스 변경은 자동 빌드하며, 확장 코드는 **Developer: Reload Window**로 다시 적용합니다. 개발 실행은 확장 저장소 루트의 `.env`만 읽습니다. 주소 우선순위는 **프로세스의 `PSB_API_URL` → 개발 실행의 `.env` → 기본 서비스 주소**입니다. 풀이 폴더의 `.env`나 VS Code 워크스페이스 설정으로 서버를 바꾸지 않습니다.

Windows·WSL·macOS에서 같은 방식으로 실행합니다. WSL·SSH에서 실행되는 확장의 `127.0.0.1`은 해당 WSL·원격 환경을 가리킵니다. `.env`는 Git과 설치 패키지에서 제외되며, 설치된 확장은 `.env`를 읽지 않습니다.

## 검증

클라이언트의 타입·저장 로직·화면 동작은 다음 명령으로 검사합니다. 이 검사들은 실제 AI 작업을 실행하지 않습니다.

```sh
pnpm compile
pnpm test:unit
pnpm exec playwright install chromium
pnpm test:ui
```

실제 확장 실행을 검사하려면 관리자가 제공하는 **로컬 통합 테스트용 백엔드**를 먼저 실행해야 합니다. 일반 운영 서버를 테스트 대상으로 사용하지 않습니다.

```sh
# 테스트 백엔드 기본 주소: http://127.0.0.1:4011/api
pnpm test:host
```

다른 주소는 `PSB_API_URL`로 지정합니다. 테스트 서버가 없으면 즉시 종료합니다. 각 실행 전 테스트 서버를 새로 시작해야 하며, 서버 구현과 실행 방법은 비공개로 관리합니다. 이 검사는 기록·자동 준비·스트리밍·초안 복원·사용량과 Ghost 내보내기를 확인합니다. Linux에서는 GUI 디스플레이가 필요하며 `VSCODE_EXECUTABLE`로 VS Code 실행 파일을 지정할 수 있습니다.

## 설치 패키지 만들기

```sh
pnpm package:vsix
code --install-extension dist/ps-blogself.vsix
```

VS Code의 **Extensions: Install from VSIX…**에서도 설치할 수 있습니다. VSIX에는 확장만 들어가며 백엔드는 포함되지 않습니다. 설치 후 서비스에 로그인해 사용합니다.
