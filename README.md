# PS-Blogself

PS-Blogself는 알고리즘 문제를 풀며 저장한 C·C++·Python 코드의 수정 기록을 풀이 글로 정리하는 VS Code 확장입니다. 처음 시도한 풀이와 마지막 코드를 다시 보면서, 어디서 막혔고 어떻게 해결했는지 글에 담을 수 있습니다.

수정 기록에서 파일을 고르면 AI가 주요 변경 구간을 골라 메모를 제안합니다. 여기에 풀이 의도를 보태고 **글쓰기**를 누르면 초안이 만들어집니다. VS Code에서 초안을 다듬은 뒤 Markdown·HTML로 저장하거나 Ghost 블로그에 게시하세요.

## 사용하기

처음 실행하면 Welcome 탭이 열립니다. **이 창의 코드 파일**에는 열린 탭과 현재 작업 폴더의 코드가 마지막 수정 시각이 최신인 순서로 표시됩니다. 파일명을 눌러 열거나 **코드 목록 열기**에서 이름·경로로 검색해 선택하세요. 아직 폴더를 열지 않았다면 **폴더 열기**를, 열린 폴더에 코드가 없다면 **코드 파일 만들기**를 사용할 수 있습니다. 파일명 아래에는 `python • 3분 전`처럼 언어와 마지막 수정 후 지난 시간이 표시됩니다. 수정 기록이 없는 파일은 디스크의 수정 시각을 기준으로 합니다. 명령 팔레트의 **PS-Blogself: 시작하기 (Welcome)**에서 Welcome 탭을 다시 열 수 있습니다.

1. VS Code에 확장을 설치하고 PS-Blogself 사이드바를 엽니다.
2. **로그인**에서 브라우저 인증을 완료합니다.
3. C·C++·Python 파일을 수정하고 저장합니다. 먼저 체험하려면 Welcome에서 **예제 코드로 테스트**를 눌러 예제 풀이의 수정 기록으로 글쓰기를 시작하세요.
4. 수정 기록을 열어 AI가 준비한 구간과 설명을 확인합니다. 설명은 바로 수정할 수 있습니다.
5. **글쓰기 열기**를 누른 뒤 사이드바의 **글쓰기**로 초안을 생성합니다. 완성된 글은 VS Code 안에서 편집하고 내보냅니다.

수동 저장은 로컬 기록에 바로 남습니다. 입력 중에는 10초간 멈추거나 30초 동안 계속 수정하면 기록을 남깁니다. **수정 기록으로 메모 자동 생성**을 켜고 로그인하면, 파일 수정이 5분간 멈추거나 창을 30초 이상 떠나거나 다른 기록 대상 파일로 전환한 지 1분이 지났을 때 의미 있는 변경을 모아 메모를 준비합니다. 파일별 자동 요청 간격은 10분이며, 파일 메뉴·수정 기록·글쓰기를 열면 바로 확인합니다. 자동 메모는 무료 크레딧 안에서 글쓰기 한 번의 예상 사용량을 남겨 두고 진행합니다. 기존 메모와 직접 고친 설명은 보존하고 새 구간만 덧붙입니다. 수동 저장 및 파일과 연결된 실행 지점은 변경 묶음에 남습니다. 메모가 12개에 도달하거나 삭제된 기록 때문에 기존 구간을 연결할 수 없으면 **메모 다시 생성**으로 전체 흐름을 재구성할 수 있습니다. 설정을 끄면 **메모 생성**을 눌렀을 때만 준비합니다.

## 수정 기록과 설정

- 파일 행을 클릭하면 **파일 열기 / 수정 기록 보기 / 글쓰기**를 선택할 수 있고, 더블클릭하면 파일이 열립니다.
- **코드 파일** 목록에는 수정 기록이 있는 파일과 새로 발견한 `.c`, `.cpp`, `.py` 파일이 함께 최신 수정순으로 표시됩니다. 폴더를 열지 않은 창에서는 마지막으로 활성화한 파일의 폴더를 사용합니다. 탐색은 화면을 연 뒤 백그라운드에서 진행합니다.
- 모든 파일에서 **수정 기록 보기**를 사용할 수 있습니다. 첫 기록 전에는 같은 수정 기록 페이지에 마지막으로 저장된 코드 전체가 추가된 항목 하나를 표시합니다. 항목의 날짜는 파일의 마지막 수정 시각입니다. 목록은 처음 20개를 표시하고 스크롤할 때 이어서 불러옵니다.
- 제목 옆 검색 버튼으로 기록이 있는 파일과 새로 발견한 파일을 함께 검색합니다. 검색어에 `/` 또는 `\`가 있으면 경로도 검색합니다. 검색어를 지우면 처음 20개부터 다시 표시합니다.
- 사이드바 제목 오른쪽 **설정**에서 활성 경로, 대상 확장자, 기록 여부, 메모 자동 생성을 변경합니다.

활성 경로의 기본값은 **현재 열려있는 모든 파일**입니다. 이 상태에서는 워크스페이스 밖에서 연 파일도 대상 확장자에 맞으면 기록합니다. 폴더를 지정하면 해당 경로 안의 파일만 기록하고, 재설정 버튼을 누르면 기본값으로 돌아갑니다.

활성 경로·대상 확장자·기록 여부는 워크스페이스별로 저장합니다. 같은 워크스페이스를 연 창끼리는 설정을 동기화하고, 검색어와 스크롤 위치는 각 창에서 유지합니다.

**현재 폴더로 설정**은 해당 창의 활성 경로에만 적용합니다. 이때 **이 창** 표시가 나타나며, 이후 그 창에서 폴더를 선택하거나 경로를 직접 입력·재설정해도 다른 창의 경로에 영향을 주지 않습니다. 창을 닫거나 **Developer: Reload Window**로 다시 불러오면 작업 공간에 저장된 경로로 돌아갑니다.

## 글쓰기와 내보내기

Welcome에서 파일 옆 **글쓰기**를 누르면 편집 페이지와 사이드바가 함께 열립니다. 수정 기록이 없는 파일도 마지막 저장본으로 시작할 수 있습니다. **변경사항 요약**에서 메모를 만들고 글 구성·문체·모델을 선택합니다. 사이드바의 **글 확인/수정**에서 본문을 편집합니다. **설정 → 고급 → 글쓰기에서 Markdown·미리보기 표시**를 켜면 **글 다시 쓰기** 아래에서 편집, Markdown, 미리보기를 전환할 수 있습니다. 이전 버전이 있으면 **글 버전**에서 선택해 읽거나 복원할 수 있습니다. 변경 내용은 자동 저장되며 저장 상태는 사이드바의 파일명 옆에 표시됩니다. 글쓰기와 수정 기록을 볼 때는 사이드바 아래 **코드 파일**에서 다른 파일로 이동할 수 있습니다. 목록은 사이드바 높이의 약 ⅓로 열리며, 높이가 600px 미만이면 접혀 있습니다. **코드 파일**을 눌러 직접 펼치거나 접을 수 있습니다.

글을 생성하면 **글 확인/수정** 탭이 열리고 편집기에 본문이 실시간으로 표시됩니다. 생성 중에는 제목과 본문이 잠기고, 완료되면 같은 자리에서 편집할 수 있습니다. 취소하거나 생성에 실패하면 기존 초안으로 돌아갑니다. AI가 남긴 메모나 글의 알림은 페이지 오른쪽 아래 **작성자 알림**에 마우스를 올려 확인하고, 클릭하면 펼친 채로 읽을 수 있습니다.

로그인을 누르면 `https://auth.shinem.dev/login`을 열고 진행 중인 VS Code 로그인과 자동으로 연결합니다. 코드 입력 없이 Google 또는 GitHub 인증을 같은 탭에서 진행합니다. 브라우저가 로컬 접근 허용을 요청하면 허용해 주세요. 로그인 중에만 `127.0.0.1:49629`를 사용하며 완료·취소·10분 만료 시 닫습니다. 여러 창에서는 한 번에 한 창에서 로그인합니다. 원격 환경은 해당 포트가 로컬의 같은 포트로 전달되어야 합니다.

글 구성은 **수정 과정 중심**, **풀이 해설 중심**, **알고리즘 설명 중심** 중에서 선택합니다. 문체는 했다/이다체, 합니다체, 해요체, 간결한 메모체 또는 사용자 지정으로 설정할 수 있습니다. 선택만으로 AI 작업을 시작하지 않으며 다음 준비·작성 요청에 반영합니다.

Lexical 기반 블록 편집기에서 제목·목록·인용·코드·표·이미지를 편집합니다. **+** 또는 빈 문단의 **/**로 블록을 넣고 왼쪽 핸들로 이동합니다. 이미지 파일 선택·붙여넣기·드롭과 캡션 편집을 지원합니다. **목차**로 제목 사이를 이동할 수 있습니다.

사이드바에서 **내보내기**를 펼치면 다음 기능을 사용할 수 있습니다.

- Markdown 복사 또는 파일 저장. 로컬 이미지는 문서 옆의 이미지 폴더에 함께 저장합니다.
- HTML 파일 저장. 로컬 이미지를 포함하므로 브라우저에서 바로 열 수 있습니다.
- Ghost 연결 및 초안 저장. 공개 게시는 별도 확인을 거치며 이후에는 같은 글을 갱신합니다. Ghost에서 수정한 글은 자동으로 덮어쓰지 않습니다.

VS Code에서 글을 수정하고 서버 동기화가 끝나면, 블로그 글쓰기 탭에서 같은 계정의 브라우저 확장을 여세요. **내 글**에서 선택하면 최신 편집본이 표시되고, **편집기에 넣기**로 옮길 수 있습니다. [브라우저 확장 설치 안내](https://github.com/molla11/ps-blogself-extension#설치와-사용)

Ghost 연결에는 해당 사이트의 Admin API 키가 필요하며 키는 VS Code SecretStorage에 저장합니다. 표·체크 목록은 Ghost HTML 카드로 변환합니다. 자세한 지원 범위는 [편집기와 Ghost 내보내기](https://github.com/molla11/ps-blogself-backend/blob/main/docs/ps-blogself/lexical-ghost.md)를 참고하세요.

설정 탭의 **내보내기 → 추가할 태그**에 `알고리즘, PS, segment tree`처럼 쉼표로 구분해 입력하고 **적용**을 누르세요. Ghost에는 기존 태그를 유지하며 추가하고, Markdown 저장·복사에는 `tags` 메타데이터, HTML에는 키워드로 포함합니다. 태그 안의 공백은 유지하며 중복과 빈 항목은 정리합니다. 비워두면 태그를 추가하지 않습니다.

문의와 크레딧 충전 요청은 **hsjang635@gmail.com**으로 보내주세요.

설정의 **Ghost 자동 업로드**를 켜면 글 생성 완료 시 연결된 Ghost에 올립니다. **Draft**는 비공개 초안 저장, **Publish**는 별도 확인 없이 공개 게시입니다. 기본값은 꺼짐·Draft이며, **Ghost 연결 / 변경**에서 연결할 수 있습니다. 자동 업로드 설정은 이 클라이언트에 저장됩니다. 생성 중 편집해 보류된 결과는 **새 결과 적용**을 누른 뒤 업로드합니다. Draft 모드에서는 이미 공개된 글을 자동으로 수정하거나 비공개로 바꾸지 않습니다.

## 저장과 복원

수정 기록과 편집 초안은 로컬에 저장합니다. 기기에서는 이전 글을 최대 20개 버전으로 보관하며 내용이 같거나 줄 끝 공백만 다른 경우에는 버전을 추가하지 않습니다.

로그인해 만든 글은 이후 저장한 제목·본문·편집 서식도 같은 계정의 서버 작업에 버전별로 동기화됩니다. 연결이 끊기면 로컬에 대기했다가 같은 계정에 다시 연결됐을 때 전송합니다. 삽입한 로컬 이미지의 참조는 편집본에 포함되며 이미지 파일은 기기에 보관합니다. 이전 확장에서 만든 글은 글을 연 뒤 **PS-Blogself: 기존 로컬 글을 서버 작업에 연결**에서 원래 작업을 선택하면 현재 편집본부터 동기화됩니다. **로그인 / 계정 → 서버 작업 기록 삭제**에서 작업을 삭제하면 서버의 입력·생성 결과·해당 편집 버전이 함께 삭제됩니다.

같은 VS Code 프로필·실행 환경의 창들은 기록과 초안을 공유합니다. 같은 글은 한 창에서 편집하고 다른 창에서는 읽기 전용으로 확인합니다. **이 창에서 편집**으로 편집권을 옮길 수 있습니다.

시작한 AI 작업은 창을 닫아도 계속됩니다. 다시 열면 기존 작업 ID로 결과를 조회하며, 연결 실패만으로 새 생성 요청을 자동 제출하지 않습니다. 서비스에 연결할 수 없어도 설치된 확장의 기존 기록 열람과 로컬 초안 편집은 가능합니다.

코드 파일은 UTF-8 기준 512KiB까지 기록합니다. 큰 파일의 새 기록은 중지하되 기존 이력은 유지하며, 긴 이력은 AI 요청에 들어갈 범위를 줄여 처리합니다.

## 계정·크레딧·전송 데이터

전체 공지와 본인 대상 공지는 사이드바 맨 위에 표시합니다. 보이는 사이드바는 활성 창에서 30초마다 갱신하고, 다시 열거나 창으로 돌아오면 바로 확인합니다. 제목을 눌러 펼치고 닫을 수 있으며 로그인 상태의 닫기는 계정에 저장됩니다. 로그인 전에는 전체 공지만 표시하고 닫기를 로컬에 저장합니다. 공지 조회에는 AI 호출이나 크레딧 소모가 없습니다.

사이드바의 무료 사용량·한도·유료 잔액은 계정의 크레딧 정보를 표시합니다. 계정이나 사용량 버튼에서 세부 내용을 확인할 수 있습니다. 조회에 실패하면 사용량 확인 불가로 표시합니다.

글을 준비하거나 생성할 때 선택한 코드·변경 내용·설명·작성 요청이 글쓰기 서비스와 AI 서비스에 전송됩니다. 로그인 토큰은 VS Code SecretStorage에 저장합니다. Ghost로 내보낼 때는 선택한 글과 필요한 이미지를 해당 Ghost 사이트로 전송합니다.

## 개발하기

Node.js 24, pnpm 12.16.1, VS Code 1.108.1 이상을 기준으로 개발합니다.

```sh
git clone https://github.com/molla11/ps-blogself.git
cd ps-blogself
pnpm install --frozen-lockfile
code .
```

**F5 → Run Extension**으로 Extension Development Host를 엽니다. 터미널에서는 `pnpm dev /path/to/problem-folder`를 사용할 수 있습니다.

소스 변경은 자동 빌드하며, 확장 코드는 **Developer: Reload Window**로 다시 적용합니다. 개발 환경 변수는 `.env.example`을 참고해 확장 저장소 루트의 `.env`에 지정합니다. `.env`는 Git과 설치 패키지에서 제외됩니다.

Windows·WSL·macOS에서 같은 방식으로 실행합니다.

## 검증

클라이언트의 타입·저장 로직·화면 동작은 다음 명령으로 검사합니다. 이 검사들은 실제 AI 작업을 실행하지 않습니다.

```sh
pnpm compile
pnpm test:unit
pnpm exec playwright install chromium
pnpm test:ui
```

```sh
pnpm test:host
```

통합 테스트는 기록·자동 준비·스트리밍·초안 복원·사용량과 Ghost 내보내기를 확인합니다. Linux에서는 GUI 디스플레이가 필요하며 `VSCODE_EXECUTABLE`로 VS Code 실행 파일을 지정할 수 있습니다.

## VSIX 다운로드와 배포

[최신 GitHub Release](https://github.com/molla11/ps-blogself/releases/latest)의 **Assets**에서 `ps-blogself-<버전>.vsix`를 받아 VS Code의 **Extensions: Install from VSIX…**로 설치합니다.

일상 개발은 `develop`에 직접 커밋하고 `git push origin develop`으로 올립니다. GitHub Actions는 `develop`과 `main`의 푸시 및 두 브랜치 대상 PR에서 단위 테스트와 Chromium UI 테스트를 실행합니다. 타입 검사와 린트를 통과한 VSIX를 새 VS Code 프로필에 설치하고 Welcome 탭이 열리는지 확인합니다. 통과한 패키지는 해당 실행의 **Artifacts**에서 14일간 받을 수 있습니다. 별도의 로컬 테스트 백엔드가 필요한 전체 통합 테스트는 위의 `pnpm test:host`로 실행합니다.

새 버전을 배포할 때는 `develop`에서 `package.json`의 `version`을 올리고 `main`으로 병합합니다. `main`의 CI가 통과하면 같은 VSIX가 `v<버전>` GitHub Release에 자동으로 올라갑니다. 이미 배포한 버전의 VSIX는 보존합니다.

## 설치 패키지 만들기

```sh
pnpm package:vsix
code --install-extension dist/ps-blogself.vsix
```

VS Code의 **Extensions: Install from VSIX…**에서도 설치할 수 있습니다. 설치 후 서비스에 로그인해 사용합니다.
